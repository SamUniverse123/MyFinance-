# Dashboard charts and stat cards use the Bklit UI registry, not the existing plain chart wrapper

`chart-area-interactive.tsx` and `chart.tsx` establish a pattern of hand-building charts on the generic shadcn `ChartContainer` wrapper directly over `recharts` primitives. For the dashboard's cashflow chart and stat tiles, we're instead installing components from the Bklit UI registry (`ui.bklit.com`, itself a shadcn-compatible registry — added via `pnpm dlx shadcn add @bklit/<name>`, same mechanism as any other shadcn component) — specifically `@bklit/area-chart` for the cashflow chart and the `stat-card-area-01`/`stat-card-line-01` blocks for the four stat tiles.

This is a deliberate per-page choice, not a repo-wide migration: `chart-area-interactive.tsx`'s existing pattern is untouched. A future reader should not "fix" the dashboard to match the old hand-built pattern, nor assume Bklit is now the house standard to extend everywhere — it was chosen here specifically for its finance-dashboard-shaped stat cards (gradient/line sparklines) that the plain wrapper doesn't provide out of the box.

**Two adaptations, both to avoid a paid dependency and a packaging bug — not scope creep:**

- `trend-badge.tsx`'s upstream version renders its arrow via `@central-icons-react/all`, which requires a paid `CENTRAL_LICENSE_KEY` (its `preinstall` script calls a license-check API and throws without one). Swapped for `lucide-react`, already this app's icon library everywhere else — same visual result, no license dependency, no other file in the registry blocks needed it.
- Bklit's charts are built on `@visx/*` (curve, gradient, shape, event, responsive, scale, grid, group, point — all `4.0.x-alpha.0`), not `recharts`. Every one of those alpha packages ships ESM with **extensionless relative imports** (`from './shapes/Arc'` instead of `'./shapes/Arc.js'`). Bundler resolution (Vite/esbuild) tolerates this; Node's strict ESM resolver used for SSR does not, and TanStack Start's SSR silently falls back to client-only rendering with a "Switched to client rendering because the server rendering errored" marker in the HTML rather than a hard 500 — easy to miss unless you check server logs or grep the rendered page for expected content. Fixed via `pnpm patch` on each affected package (see `patchedDependencies` in `pnpm-workspace.yaml`, patch files in `patches/`), mechanically appending the missing `.js`/`.js` extensions to every relative and `lodash/*` import in each package's `esm/` output. This is why the dashboard has 8 `pnpm patch` entries for packages nobody in this repo installed directly — they're transitive Bklit dependencies, and removing the patches (e.g. during a routine `@visx/*` version bump) will silently break dashboard SSR again without necessarily throwing an error you'd notice.
